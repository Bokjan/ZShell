# ZShell 架构

个人使用的跨平台（macOS / Windows）SSH / Telnet / 串口终端。本文只记录跨模块的设计决策和它们的理由；模块内的细节（边界情况、库的坑、具体数值）写在代码注释里，这里指向对应的文件。

## 技术栈

| 层 | 选型 |
|---|---|
| 应用框架 | Tauri 2 |
| 后端 | Rust + tokio |
| SSH / SFTP | `russh`（`ring` 加密后端，避免 Windows 上依赖 CMake/NASM）/ `russh-sftp` |
| 凭据 | `keyring`（macOS Keychain / Windows Credential Manager / Linux Secret Service） |
| 加密 | `ring`（AES-256-GCM、PBKDF2-HMAC-SHA256、随机数），`zeroize` |
| ssh_config 导入 | `ssh2-config` |
| 本地终端 | `portable-pty`（Windows 走 ConPTY） |
| 串口 | `serialport` |
| Telnet | 自己实现（协议与选项协商） |
| 前端 | Vite + React + TypeScript |
| 终端渲染 | `@xterm/xterm` + fit / webgl / unicode11 / web-links / search 插件 |

## 总体结构

```
┌──────────── 前端 (React + xterm.js) ────────────┐
│ 会话列表 │ 终端标签页 │ SFTP 面板 │ 端口转发面板 │
└───────────────┬──────────────▲─────────────────┘
          invoke (输入/命令)    │ Channel (输出字节流/事件/进度)
┌───────────────▼──────────────┴─────────────────┐
│ SessionManager: 会话任务（SSH / Telnet / 串口 / 本地 PTY）│
│ Connections: 会话 id → 已认证的 SSH 连接         │
│   一个 SSH 连接 ──┬─ shell channel              │
│                   ├─ sftp subsystem channel     │
│                   └─ direct-tcpip / forwarded   │
│ auth / known_hosts / vault / config / settings  │
└─────────────────────────────────────────────────┘
```

| 模块（`src-tauri/src/`） | 职责 |
|---|---|
| `session/` | 会话抽象：`TermIo`、`SessionManager`、`SessionSink`、输出流控 `Flow` |
| `ssh/` | 连接与 shell（`mod.rs`）、russh 回调（`handler.rs`）、主机密钥确认（`host_key.rs`）、known_hosts（`known_hosts.rs`）、认证（`auth.rs`）、连接注册表（`connections.rs`） |
| `sftp/` | 浏览与文件操作（`mod.rs`）、传输（`transfer.rs`）、本地编辑（`edit.rs`）、拖出（`drag/`）、替换写入（`replace.rs`）、文件名转码（`names.rs`） |
| `forward/` | 转发规则的运行（`mod.rs`）、`-L` / `-R` / `-D`（`local.rs` / `remote.rs` / `dynamic.rs`）、SOCKS（`socks.rs`） |
| `pty/` | 本地终端（`mod.rs`）、默认 shell 与环境变量（`shell.rs`） |
| `telnet/` | Telnet 会话与自动登录（`mod.rs`）、协议与选项协商（`protocol.rs`） |
| `serial/` | 串口会话与设备列表（`mod.rs`） |
| `net.rs` / `proxy/` | 出站连接（直连或经代理）、`Route`；代理：SOCKS5、HTTP CONNECT、ProxyCommand |
| `zmodem/` | rz / sz：检测与接管、帧格式、收发 |
| `logging.rs` | 会话日志：写入线程、格式、索引 `logs.json` 与清理 |
| `config.rs` / `quick.rs` / `settings.rs` | 会话、文件夹与代理；快速命令；应用设置 `settings.json` |
| `vault.rs` / `crypto.rs` / `secrets.rs` | 保险库（上面几类数据与密码存在哪里、如何保护）；加密与口令派生；系统凭据存储 |
| `applock/` | 应用锁：锁定状态、各平台的系统认证、闲置与锁屏检测 |
| `persist.rs` | JSON 文件的读写：读不出的文件、原子写入、手写文件的 id |
| `encoding.rs` / `local_name.rs` | 会话的字符编码；对方给出的文件名转成本地文件名 |
| `import.rs` / `backup.rs` | ssh_config 导入；会话导出与导入 |
| `window.rs` | 窗口：按平台创建，新窗口要显示的内容，退出前询问各窗口；macOS 的红绿灯，Windows 的窗口按钮与贴靠边框 |
| `i18n.rs` / `error.rs` | 后端消息目录、结构化错误（见 [I18N.md](I18N.md)） |
| `commands/` | Tauri 命令入口，按领域分文件 |
| `bindings.rs` | 生成前端的 TypeScript 类型和共用常量（`src/lib/bindings.ts`） |

前端（`src/`）：

- **标签页与窗格**：状态在 `lib/tabs.ts` 的 store 里，每个修改是一个 action，由纯函数 `reduceTabs` 处理，修改后立即生效，不等渲染。`App.tsx` 订阅并分发；关闭流程、撰写栏、快速命令、全屏各是 `app/` 下的一个 hook。`TabPage` 只在自己的标签变化时重绘。
- **窗格的会话**：`lib/sessionRegistry.ts` 为每个窗格建一个 `PaneSession`（`lib/paneSession.ts`），负责打开会话、重连、共享连接、登录后命令和流控，只经一个小接口读写终端；`TerminalView` 只管终端本身。
- **解锁**：`main.tsx` 里 `SettingsProvider` 之下是 `VaultGate`，保险库锁定时只显示 `UnlockScreen`，解锁后才挂载 `AppLockGate` 与其中的 `App`（见「加密保险库」「应用锁」）。
- **对话框与快捷键**：对话框经 `useDialog`（`lib/dialogs.ts`）登记到一个栈，只有最上层的响应 Esc 与点击背景；快捷键经 `useShortcuts`（`lib/shortcuts.ts`）在捕获阶段统一分发，注册时说明何时生效。
- **其他**：`lib/api.ts` 封装全部后端命令，类型来自生成的 `lib/bindings.ts`。纯逻辑模块有 vitest 单元测试（`*.test.ts`）。

## 设计决策

### 会话与数据流

- **前后端类型**：与前端交换的 Rust 类型派生 ts-rs 的 `TS`，生成一个提交到仓库的 `src/lib/bindings.ts`，`cargo test` 在它过时时失败，只改了一边的类型在 CI 里就会发现。错误码是从英语语言包生成的联合类型 `ErrorCode`，前端按错误码分支由 `tsc` 检查。两边都要用的少量常量（可选的编码、新会话的默认终端类型和串口设置、默认快速命令分组的 id）也从后端的定义写进这个文件，`api.ts` 转出，前端不再另写一份。选 ts-rs 而不是 specta 的理由见 `bindings.rs`。
- **打开会话**：只有一个命令 `session_open`，参数是 `SessionSpec`（保存的会话、快速连接、复制标签、本地终端），先解析成后端（`Backend`），日志与会话任务只在一处建立。
- **会话是一个后台任务**：`SessionManager` 为每个会话创建 `TermIo`（输出 / 事件 Channel、输入队列），后端任务持有它运行；新的后端只需实现同样的任务形态。
- **会话的关闭**：`SessionManager::remove` 是唯一的入口。任务之外的资源（连接登记、等待回答的 ZMODEM、流控）登记在会话的 `Lifetime` 上，无论是关闭、会话自己结束还是任务被丢弃，都只释放一次，与调用顺序无关（`session/`）。
- **会话属于 webview**：页面重新加载或窗口销毁时关闭该 webview 的全部会话，否则它们无人显示、也无人关闭；打开中途页面重载的会话被拒绝（`session.pageGone`）。会话可以移到另一个窗口（见「多窗口」），归属随之改变。
- **终端输出不走 event**：经 Tauri `Channel` 推送原始字节，前端直接 `term.write(Uint8Array)`；会话事件走同一个 channel，保证"连接已关闭"总在最后一段输出之后。输入走 `invoke`。
- **背压**：每条数据通路都有上限。终端输出由前端按已处理字节确认，后端未确认过多时暂停读取（`Flow`），因为 Tauri 的 IPC 队列没有上限、xterm.js 积压过多会丢弃写入；SSH 写入等服务器窗口时仍持续读取，否则 russh 的有界队列会死锁；ZMODEM 与日志同样有界。代价是暂停读 SSH shell 会让同一连接上的 SFTP 和转发一起等，但比内存无限增长好。具体阈值见 `session/`。
- **字符编码**：应用内部一律 UTF-8，只在与远端交界处按会话的 `encoding` 转换：输出（`SessionSink`，流式解码，日志记的是转码后的文本）、输入（`TermIo::recv`；二进制的鼠标报告原样发出）、SFTP 文件名（`sftp/names.rs`，有不可逆名字的已知限制）、ZMODEM 的文件名。快速连接、本地终端与认证提示总是 UTF-8。
- **会话事件**：`Connected`、`Forward`、`Zmodem`、`Closed { reason, status, error }`；`reason` 区分 `exited`、`lost`、`failed`，前端据此决定重连、自动关闭或提示。
- **命令在哪个线程上运行**：Tauri 的同步命令跑在主线程，等待会卡住窗口，所以碰文件、凭据存储或设备列表的命令是 async 的，阻塞部分放进 `spawn_blocking`（`commands/mod.rs`）；会话任务里读密码用异步接口，凭据存储等用户授权时其他标签照常运行。例外：前端连续发出、整体替换的写入（设置、快速命令、转发规则）是同步命令，保证最后发出的最后写入。
- **内容安全策略**：`tauri.conf.json` 设了严格的 CSP 作为纵深防御（IPC 能执行命令、写任意文件），资源只来自应用自身。样式需要 `unsafe-inline`（xterm.js 插入 `<style>`，`index.html` 有首帧的内联样式），为此关掉 Tauri 给 `style-src` 加的 nonce，有 nonce 时浏览器会忽略 `unsafe-inline`。

### SSH

- **一个连接多路复用**：认证后连接登记到 `Connections`，SFTP 与端口转发开在同一连接上；批量传输另开一个 SFTP channel，免得列目录排在大文件的读请求后面。
- **复制标签**：已连接的 SSH 标签复制或分屏时，在源连接上开新的 shell channel，不重新连接认证（类似 ControlMaster）。多个会话可以指向同一连接，最后一个结束时才断开；源连接已断开时照常新建连接。
- **提示都在终端里**：主机指纹、密码、口令、keyboard-interactive 都经 `TermIo::read_line` 在终端里问，与 OpenSSH 一致，不弹窗。
- **认证**："自动"按 OpenSSH 的顺序尝试 agent、私钥、keyboard-interactive、密码；加密的私钥只在服务器接受其公钥后才问口令。多因素认证按服务器返回的剩余方法继续；保存的密码只回答一次，验证码类的提示总在终端里问，以免把密码当验证码提交（`ssh/auth.rs`）。
- **主机校验**：自己解析 `~/.ssh/known_hosts`（`ssh/known_hosts.rs`），按 OpenSSH 的规则校验与写入，并只读地参考 `known_hosts2` 与系统文件，不用 russh 自带的校验。指纹变化时告警并拒绝连接；只记录了其他类型的密钥时先列出再问，与 OpenSSH 措辞一致。
- **agent 转发**：只转发给目标主机，只在本连接请求过转发时接受服务器开的 agent 通道。
- **ProxyJump**：在上一跳连接上开 `direct-tcpip` channel 作为下一跳的传输层，每一跳用被引用会话自己的地址和认证，主机密钥按各跳自己的地址校验。建跳板的部分（`ssh::tunnel`）SSH 与 Telnet 共用。
- **keepalive 与重连**：连续 3 次 keepalive 无响应判定断线（`lost`），前端按退避间隔一直重连到标签关闭，认证或主机密钥被拒绝时停止。russh 认证完成后才发 SSH keepalive，之前靠同样间隔的 TCP keepalive（直连和 SOCKS / HTTP 代理）。认证途中连接断开算断线（`net.connectionLost`），会继续重连；服务器主动断开（例如 sshd 超过 `MaxAuthTries`）算认证失败（`auth.disconnected`），和 OpenSSH 一样停下。重连是新会话；会话结束时后端先重置终端模式，免得下一个 shell 把鼠标报告当成输入。连接各阶段有超时，认证阶段没有（服务器有自己的限制），见 `net.rs` 与 `ssh/mod.rs`；握手超时或标签关闭时连接会被结束，不会留在 russh 的连接任务里（`ssh/abortable.rs`）。

### Telnet 与串口

- **会话配置**（2.0 起）：会话是共同字段加按 `protocol` 区分的 `connection`（`ssh`、`telnet`、`serial`），改协议后只留新协议的字段。各后端只接收自己协议的配置。2.0 之前的扁平格式不读取，按"读不出的文件"处理。
- **协议**：快速连接支持 SSH 与 Telnet；文件与转发面板、复制标签只用于 SSH，串口设备只能打开一次。
- **Telnet**：协议层是纯状态机（`telnet/protocol.rs`），经 `net::connect` 或跳板机通道连接。服务器关闭连接算 `exited`，读写出错算 `lost`。保存的用户名与密码由后端在登录提示处各填一次，密码不经过前端。
- **串口**：阻塞句柄各用一个线程读写；拔出设备算 `lost`，前端按断线重连的节奏重试，插回后自动接上。

### 代理

- **配置**：代理是独立保存、有名称的配置（SOCKS5、HTTP CONNECT、命令），会话按 id 引用；被引用的代理不能删除，而不是悄悄改成直连。
- **只用于第一个连接**：代理取第一台跳板机自己的设置，没有跳板机时取会话的，与 OpenSSH 一致（`ProfileStore::route` → `net::Route`）。快速连接不经代理。
- **接入点**：`net::connect` 是 SSH 第一跳与 Telnet 的唯一入口，有代理时交给 `proxy::connect`，返回任意字节流。
- **安全**：主机名交给代理解析。ProxyCommand 代入的主机名与用户名不能含 shell 元字符等（同 OpenSSH 对 CVE-2023-51385 的处理），导入别人的会话文件不应能借此执行命令（`proxy/command.rs`）。代理需要密码时同样在终端里询问。

### 文件传输与端口转发

- **SFTP 传输**：先扫描生成计划再逐个复制，进度经 Channel 推送；关闭窗格时取消其文件面板里的传输。覆盖已有文件时先写临时文件再替换，取消、出错或断线时原文件不变（`sftp/replace.rs`）。
- **本地文件名**：下载、拖出、本地编辑与 ZMODEM 接收都经 `local_name`，保证结果是目标文件夹里的一个文件名，自动加序号的名字在选定时就占住（`local_name.rs`）。
- **SFTP 面板**：选择、排序、过滤在前端完成。不选位置的下载进设置里的下载文件夹。
- **用本地编辑器编辑**：后端下载到临时目录并监视；上传由前端经标签当前的连接发起，所以重连后继续有效。远端在下载后被改过时先询问再覆盖（`sftp/edit.rs`）。
- **拖出窗口**：只有放到其他应用上才下载，macOS 用文件承诺、Windows 用 OLE 拖放，对方真正取数据时才下载（`sftp/drag/`）。
- **端口转发**：规则存在会话配置里。规则的每次运行是一个持有全部资源的任务，停止即等资源释放，端口立即可重用（`forward/mod.rs`）。规则属于会话，同一会话的多个标签各有连接，所以一条规则只在其中一条连接上运行，从任一标签操作都落到那条连接上；关闭它所在的最后一个标签时可以移到同会话的其他标签继续。

### ZMODEM

- **位置**：在会话层，SSH、Telnet、串口与本地终端（包括在本地终端里 ssh 登录后）都适用。协议自己实现，以 lrzsz 为对照测试。
- **检测与接管**：`SessionSink::output` 查找 `sz` / `rz` 的开头；识别后输出交给传输任务，按键被丢弃，Ctrl+C 取消。误判（如 `cat` 了一个二进制文件）时输出原样交还终端。传输数据计入会话的流控。
- **与前端交互**：经 `Zmodem` 会话事件询问保存位置或要发送的文件。接收默认先在终端上方提示，因为 `cat` 一个恰好像 `sz` 输出的文件也会触发，不应在用户不知情时存下文件。进度与结果由后端写在终端里。
- **兼容性**：转义全部控制字符（相当于 `rz -e`），以通过过滤控制字符的堡垒机。细节见 `zmodem/`。

### 本地终端

- 作为 `SessionManager` 的另一种后端，输入、resize、关闭沿用 SSH 会话的命令。
- **前台进程**：`session_foreground` 报告 shell 之外在前台运行的程序，用于关闭前确认。
- **默认 shell 与结束**：macOS 以登录 shell 启动，补全从 Finder 启动时缺失的 PATH；Windows 优先 PowerShell 7（`pty/shell.rs`）。以子进程退出为准判断结束；shell 以 0 退出时自动关闭所在窗格，否则按 Enter 重启。

### 配置与设置

- **存储**：配置目录（macOS `~/Library/Application Support/org.boyin.zshell/`，Windows `%APPDATA%\org.boyin.zshell\`）。会话、文件夹、代理、快速命令与密码由保险库管理（见「加密保险库」）；`settings.json` 与 `logs.json` 总是明文。unix 上目录为 0700，文件创建时即为 0600。保存会话或代理时密码写入失败不算保存失败（`Saved`），对话框改为编辑这一项，再次保存不会新增一份。
- **单实例**：两个进程会互相覆盖配置。Windows 用 single-instance 插件；macOS 与 Linux 按配置目录加锁（`instance.rs`，`flock`），第二个实例把已有的提到前台后退出。macOS 只在打开同一个 `.app` 时复用已有实例（另一个副本、`open -n`、直接运行可执行文件都会再开一个）；插件在 macOS 上的锁与 HOME 无关，会挡住端到端测试的隔离实例。
- **读不出的文件**：配置文件都经 `JsonFile`（`persist.rs`）读写。内容读不出的改名保留，从空开始；文件本身读不出的留在原处、本次运行不再写它。应用不因此无法启动，之后的保存也不覆盖原文件，前端启动后列出这些文件。写入是临时文件加改名，几个文件先全部写好再依次改名。
- **设置**：前端 `SettingsProvider` 启动时读取，修改即时生效并保存，后端校验。界面文字大小经 CSS 变量 `--text-scale` 缩放，标题栏、图标与终端不变。主题经 `<html data-theme>` 选择 CSS 变量组，原生窗口同步跟随。
- **会话与文件夹**：文件中的顺序即显示顺序；拖拽只有一个后端操作 `tree_move`。删除文件夹时内容移到上一级。加载时修正坏引用和循环；指向暂时读不出的文件夹或代理的引用保留，文件恢复后即恢复，找不到代理的会话报错而不是直连。
- **导出 / 导入**：JSON 文件（`format: "zshell-sessions"`、`version: 2`），含文件夹、会话与代理，可选带密码（见「加密保险库」）。导入时已存在的会话、代理按名称或地址匹配，不重复导入；跳板机与代理随所选会话一并导入；列表里显示导入后会执行的代理命令与会监听的转发规则；文件在显示后变了则拒绝导入，导入的总是显示过的内容。文件可能是别人的，导入的内容经过与保存时相同的校验（`backup.rs`）。
- **快速连接**：不需要已保存的会话；"另存为会话"改变标签的目标但不重连。
- **会话日志**：后端在 `SessionSink::write` 里把终端显示的内容交给日志线程，不经过前端，所以不回显的密码不会进日志；日志慢时丢弃放不下的部分并记下缺了多少，不拖住会话。清理只针对 `logs.json` 索引里的文件（`logging.rs`）。
- **ssh_config 导入**：一次性复制，之后与 config 无关联。解析库不认识 `Match`、`Include` 也不限层数，所以交给它之前按 OpenSSH 的方式预处理（`import.rs`）。
- **`~` 与主目录**：私钥路径的 `~` 由后端展开，与 OpenSSH 用同一个目录；主目录下的私钥存成 `~/…`，导出的会话换台电脑也能用。
- **单会话外观**：会话可以覆盖配色、背景色、字体和字号，只由前端解释，编辑后已打开的标签立即应用。
- **登录后命令**：由前端在每个新 shell 出现提示符后逐条发送，用户一开始输入就放弃剩下的（`lib/paneSession.ts`）。

### 加密保险库

- **保护方式**（`vault.rs`）：未设置（2.7 之前的行为：明文文件，每个密码在凭据存储里单独一条）、不加密（密码在 `passwords.json`）、系统凭据存储（数据密钥在凭据存储里）、主密码（数据密钥以主密码派生的密钥包装，可选同时存进凭据存储）。当前方式由文件决定，不另存标记。首次启动在未设置时询问一次，只能用按钮关闭。
- **范围**：会话、文件夹、代理、快速命令与密码。`settings.json`（外观要在解锁前生效）、日志与 `~/.ssh/known_hosts` 不加密。
- **格式**：`vault.json` 是明文头加 AES-256-GCM 加密的全部数据，头部的原样字节作为 AAD，被改动即解不开。口令派生用 PBKDF2-HMAC-SHA256，参数随文件保存。导出文件里的密码同样加密，并绑定文件中的会话、文件夹与代理，改过主机或代理命令的文件用原口令解不开（`backup.rs`）。
- **读写**：`Vault` 持有全部数据，各存储有自己的副本供查询，修改经 `Vault::update` 写出。保险库读不出或解不开时保持原样，从不覆盖。
- **解锁**：启动时只读 `vault.json` 的头部，不碰凭据存储（可能弹授权框，或在 Linux 上等 D-Bus 超时）；解锁前前端只显示解锁界面，没有会话也没有标签。界面外壳（`LockScreen`）与应用锁共用。忘记主密码只能重置。
- **更改保护方式**：先写好并校验新的，再删旧的；每次都换新的数据密钥，凭据存储里残留的旧密钥打不开任何东西。任何一步停下，磁盘上的保险库都能用凭据存储里的密钥或主密码打开，残留的明文在下次解锁后删除，删不掉时解锁的窗口提示一次。启动时读不出而另存为 `<名字>.bad-<时间>` 的明文文件留给用户修复，从不自动删除；改为加密时列出它们，由用户决定是否删除（`Vault::plain_copies`）。失败路径的细节见 `Vault::set_protection`。
- **凭据存储**（`secrets.rs`）：`CredentialStore` 接口，系统实现是 keyring（Linux 为 Secret Service），测试用内存实现。Linux 上可能没有 Secret Service，这时只能选主密码或不加密。存储种类随保险库状态返回，界面文案按种类选择，前端不猜平台。

### 应用锁

- **范围**（`applock/`）：盖住窗口直到系统认证通过，会话照常运行；只锁界面，内存中的数据不重新加密（要让保险库受生物识别保护，需把数据密钥放进要求生物识别的钥匙串项，macOS 上需要开发者证书）。macOS 用 LocalAuthentication（Touch ID，没有时退回登录密码），Windows 用 Windows Hello（认证框挂在主窗口上），其他平台暂不可用（Linux 的计划见 ROADMAP「M33」）。后端报告认证方式、能否检测闲置与锁屏，前端据此显示，不猜平台。
- **状态在后端**：启动即为锁定，只有后端调用系统认证通过，或输入主密码解锁保险库，才解开；页面重载后仍然锁着。锁定时不问系统有什么认证方式（睡眠与锁屏只通知一次，而 Windows Hello 在系统挂起时可能答不上或答得慢），解锁时才问：认证方式确实没了（如删除了 Windows Hello PIN）则在锁定界面说明原因，由用户点「不经认证解锁」解开，不会自己解开，因为做到这一步需要账户密码；只是询问失败则照常要求认证。「没了」只认明确的情况：macOS 上只有未设置登录密码（`LAError::PasscodeNotSet`），其他错误都算询问失败；Windows 上 Hello 未设置、设备不在和被策略关闭都算，策略关闭也放行，因为能改策略的管理员本来就能读出进程内存里的会话，不放行则会把用户永久锁在外面。
- **设置在保险库**（`Data::app_lock`）：与会话一样受保护，加密时改文件关不掉它，否则改完重启即可绕过；不加密时是 `applock.json`；未设置保护方式时不能开启。所以 `AppLockGate` 在 `VaultGate` 之内，保险库解锁后才知道是否锁定，得到结果前什么都不显示。开启时要认证一次。
- **触发**：系统的闲置时间（不只是 ZShell 窗口，终端输出不算活动；Touch ID 与人脸不算输入，所以最多从上次解锁算起）；系统锁屏、睡眠、切换用户，在事件发生时锁定，醒来时画面已被盖住；手动（⇧⌘L / Ctrl+Shift+L，应用菜单）。
- **锁定界面**：模态 `<dialog>`，在 top layer 里盖住一切，其余页面（包括渲染到 body 末尾的对话框、菜单与提示）都变为 inert，应用保持挂载。只在窗口有焦点时自动请求认证（闲置锁定时用户可能在别的应用里），取消后只由按钮请求。
- **锁定期间**：React 之外的部分经 `lib/appLock.ts` 的 `isAppLocked()` 判断：快捷键、对话框栈的按键、`announce()`、原生拖放（不受 inert 影响），以及会话自己打开的原生对话框（ZMODEM 的文件选择，解锁后再打开）。关闭窗口的确认显示在锁定界面上。锁定时已经打开的原生文件对话框盖不住（已知限制）。

### 检查更新

- **查什么**（`update.rs`）：GitHub 上最新一个已发布 release 的版本号（`releases/latest`，不含草稿与预发布），按 semver 与当前版本比较。只提示，不下载：用户在浏览器里从 release 页面下载新版本。请求的 User-Agent 只写 `ZShell`，走系统的 TLS（Security.framework / SChannel）与系统代理。对外说明见 `PRIVACY.md`，改动行为时同步修改。
- **何时查**：设置开启时（默认开启）由后端每天最多查一次，启动后稍等片刻再查。上次检查的时间和结果存在 `update.json` 里，只是缓存，读不出就当没查过；一天内多次启动不会重复检查。手动检查随时可以：帮助菜单（macOS 在 App 菜单）的"检查更新…"打开 设置 › 关于，结果显示在那里。每次检查的结果经 `update-status` 发给所有窗口。
- **怎么提示**：没被跳过的新版本标在通往 设置 › 关于 的路上：Windows 的菜单按钮、帮助子菜单和"检查更新…"项，macOS 侧栏的设置按钮，以及设置导航里的"关于"。运行中新发现的版本在有焦点的窗口播报一次。跳过的版本存在设置里。
- **Microsoft Store 版**：有包身份（`GetCurrentPackageFullName`）时不检查，相关界面都不显示，更新由 Store 负责。

## 交互约定

### 无障碍

目标是读屏用户（VoiceOver、讲述人、NVDA）能完成连接、操作终端、使用 SFTP 与主要对话框，全部功能可以只用键盘完成；不追求逐条符合 WCAG。

- **终端**：设置里的"读屏支持"打开 xterm.js 的 `screenReaderMode`，有性能开销，默认关。系统要求更高对比度时提高终端的最低对比度，配色本身不变。
- **对话框**：`Modal` 带 `role="dialog"`（确认类为 `alertdialog`）与 `aria-modal`，以标题命名。打开时聚焦第一个控件，Tab 在最上层对话框内循环，关闭后焦点还给打开前的元素。不给根元素加 `inert`，因为 Windows 的窗口按钮在里面。
- **列表**：焦点停在列表容器上，用 `aria-activedescendant` 指向当前行。标签栏是 `tablist`，会话列表是 `tree`（搜索时为 `listbox`），文件列表是多选的 `grid`。各处菜单都可以用 Shift+F10 或菜单键打开。WebKit 对角色结构的要求见 `Sidebar.tsx` 的注释。
- **播报**：`lib/announce.ts` 是唯一的 live region，播报一闪而过或不在视线内的变化（后台窗格断开、传输完成、已复制）。
- **样式**：键盘焦点统一画强调色轮廓，去掉轮廓必须用别的方式显示焦点。尊重减少动态效果与 Windows 对比度主题；文字与背景对比度至少 4.5:1，白字所在的填充用更深的 `--accent-fill`。
- **验证**：macOS 上可以用 `osascript -l JavaScript` 经 System Events 读出窗口的辅助功能树；实际体验仍要用读屏软件试。

### 图标

- **只用 SVG**：图标全部是 `components/icons.tsx` 里的 SVG 组件，不用文字字形或 emoji：×、▾、⟳、📁 这类字符在各平台字体里的形状和基线都不同，过去多次因此错位。`icons.test.ts` 在 `icons.tsx` 之外出现 `<svg>` 或这类字符时失败（例外见测试）。
- **画法**：16×16 网格，`currentColor` 描边，`aria-hidden`，名称由所在的按钮给出（只有图标的按钮用 `IconButton`，它的 `label` 也是悬停提示）。对齐规则见 `icons.tsx`。

### 快捷键、菜单与侧栏

- **快捷键**：在捕获阶段拦截，终端收不到。所有快捷键在 `lib/keymap.ts` 的一张表里声明，按物理按键匹配，应用菜单（包括 macOS 的原生菜单栏）、右键菜单的文字和设置里的列表都由它得出，改快捷键只改这一处。Windows 上与 shell 冲突的快捷键加 Shift（Ctrl+F、Ctrl+W 留给 shell）。对话框打开时只有"打开设置"生效，免得操作对话框背后的标签。
- **终端全屏**（`app/useFullScreen.ts`）：窗口全屏并隐藏终端以外的界面（隐藏而不是卸载，退出后原样恢复）。
- **应用菜单**：结构和快捷键一起在 `keymap.ts` 里声明（`appMenu`），分为 App、文件、编辑、视图、帮助几部分。
  - macOS：页面把菜单的结构、文字和按键发给后端（`menu.rs`），后端与系统自带的项（关于、服务、隐藏、退出，编辑菜单的撤销到全选，窗口菜单）一起构建原生菜单栏。WKWebView 的 ⌘C / ⌘V / ⌘Q 等依赖原生菜单项；页面加载前菜单栏只有系统项。原生菜单项的按键先被菜单拿到，所以这些动作在 macOS 上不由页面匹配按键，而是由菜单向最近有焦点的窗口发 `menu-action`。关闭窗口与退出由后端直接处理，页面没加载或停在解锁界面时也能用；退出交给前端汇总各窗口后确认（见「多窗口」）。
  - Windows（以及将来的 Linux）：没有菜单栏。标题栏左上角的图标与名称是菜单按钮（也可按 Ctrl+Shift+M），页面内的 `ContextMenu` 把各部分显示为子菜单，App 部分的项（锁定、设置、退出）放在顶层。
- **菜单项即快捷键**：选中菜单项等于按下它的快捷键。`runAction` 用一个代表该动作的按键事件走 `useShortcuts` 的同一套处理，所以对话框、应用锁、当前终端等规则与快捷键完全一致；没有快捷键的动作（新建会话、导入导出、帮助）也在表里。页面内的菜单先把焦点还给打开它之前的位置，再执行动作，效果与按快捷键相同。Windows 的菜单在打开时按当前窗口的状态禁用不适用的项；macOS 的菜单项始终可用，不适用时什么也不做。
- **右键菜单**：页面内绘制的 `ContextMenu`（可以有子菜单），WebView 自带的右键菜单只在文本输入框里保留。
- **悬停提示**：WKWebView 不显示 `title`，所以由页面自己画（`Tooltips`），组件照常写 `title` 即可。
- **滚动条**：用系统滚动条，跟随深浅色，不用 `::-webkit-scrollbar` 自绘，以免 macOS 失去悬浮滚动条；终端的由 xterm.js 自绘。
- **会话列表**（Xshell 风格）：单击选中，双击或 Enter 打开，双击文件夹打开其中全部会话。搜索框按名称、地址、用户名过滤，输入像地址时提供快速连接。

### 标题栏

- **布局**：没有原生标题栏，窗口顶部一行在侧栏右边界处分为侧栏顶行与标签栏。窗口由 `window.rs` 按平台创建：macOS 用 Overlay 标题栏，红绿灯居中于顶行；Windows 无边框，窗口按钮自绘（`WindowControls`）；其他平台保留原生标题栏。
- **拖动**：由 `lib/window.ts` 处理带 `data-window-drag` 的元素，双击与右键交给后端，行为与系统一致；对话框遮罩顶部那一条也能拖动窗口。
- **Windows 贴靠布局**：每个窗口的最大化按钮上方放一个不绘制的原生子窗口，让系统认出它是最大化按钮（`window.rs`）。

### 剪贴板与终端输入

- 读写剪贴板用 `tauri-plugin-clipboard-manager`，因为菜单里的粘贴触发不了浏览器的 paste 事件，WKWebView 的 `readText` 又会弹出系统确认；macOS 的 ⌘C / ⌘V 仍走原生菜单。
- 所有粘贴走 xterm.js 的 `term.paste()`。多行内容在远端没开 bracketed paste 时先确认，开了则 shell 只插入不执行，无需确认。
- 远端程序开启鼠标模式时右键交给程序，Shift+右键总是打开菜单；Option 作为 Meta 只在 macOS 上可选。

### 标签页

- **分屏**：一个标签是一棵窗格树，每个窗格是独立的会话。窗格平铺渲染、按树算出的位置绝对定位，切分、关闭、调整大小都不会重新挂载其他窗格的终端（卸载即结束会话，`lib/layout.ts`）。新窗格默认复制当前窗格（SSH 复用连接）。布局不保存。
- **当前窗格**：标签的标题、状态、右键菜单与文件 / 转发面板都跟随有焦点的窗格；每个 SSH 窗格各有一份面板实例。
- **标题**：重命名的标题 > 远端标题（OSC 0 / 2，可关闭）> 会话名。
- **拖拽排序**：用鼠标事件而不是 HTML5 拖放，因为 Windows 上 Tauri 的文件拖入会拦截 HTML5 拖放。
- **关闭确认**（可关闭）：已连接的远端窗格或有前台程序的本地终端先确认；文件面板有传输、在本地编辑器里打开的文件或待回答的问题时，不论是否连接也先确认，并说明会失去什么（断线时等待重连上传的保存也在内）。文件面板的这三项与「不能移动的标签」共用一个判断（`paneWork`，`lib/panes.ts`）。关闭窗口会结束它的全部会话，有这样的标签时总是确认（`app/useCloseFlow.tsx`）。
- **撰写栏与同步输入**：纯前端实现，经各窗格的 `PaneSession.send()` 发出，只发给 shell 已就绪的窗格，不会把口令发进别的窗格的认证提示。范围只在撰写栏打开时生效，关闭后只发当前窗格，避免范围停在"所有标签"而不自知；范围超出当前窗格时有醒目的标记（`lib/compose.ts`）。
- **快速命令**：按分组整体保存，默认分组总是存在；会话可以指定其标签默认显示的分组，与撰写栏共用发送逻辑。

### 多窗口

- **窗口从标签产生**：没有空白的新窗口。标签右键菜单"移到新窗口 / 移到某窗口"、把标签拖出窗口，或会话列表的"在新窗口中连接"，才会打开窗口。第一个窗口是 `main`，之后的是 `window-N`（capability 授权 `window-*`）；新窗口在来源窗口右下方错开，大小相同。窗口要显示的内容（新窗口打开时带的标签或会话，之后其他窗口移来的标签）由后端按窗口暂存，页面启动时和收到 `tab-received` 时取走（`window_take`），后端不解读它。暂存而不是直接用事件发，是为了让还在加载的页面也拿得到，并让"关空窗口"和"移入标签"互斥（见下文"关闭与退出"）。
- **只发给一个窗口的事件**：前端 `listen()` 不指定目标时，也会收到发给其他窗口的事件，所以一律用 `lib/windows.ts` 的 `listenHere` / `useWindowEvent`（监听本窗口）。原生菜单项发给最近有焦点的窗口（`window::current`，也是 Windows 上再次启动时提到前台的窗口）。
- **跨窗口同步**：设置、会话与文件夹、代理、快速命令、保险库的保护方式、应用锁在一个窗口里保存后，后端通知其他窗口（`config-changed`），它们重新读取；设置与快速命令是整体替换的写入，重新读取让下一次写入基于最新内容。最近打开的会话在浏览器存储里，经 `storage` 事件同步。应用锁的状态本来在后端：一个窗口锁定或解锁，其他窗口跟着盖上或揭开，只有有焦点的窗口自动请求认证。
- **窗口标题**：窗口以当前标签的标题命名（macOS 的 Window 菜单、任务栏、其他窗口的"移到"菜单都用它），改变时通知其他窗口刷新列表。
- **移动标签**（`app/useWindows.ts`）：整个标签连同分屏布局与窗格状态（标题、状态、转发、日志、命令分组）作为数据交给目标窗口，目标窗口用自己的 key 插入。有会话的窗格由目标窗口接管：它建好终端与新 Channel 后请后端换通道（`session_adopt`），后端在旧 Channel 上最后发一个 `moved` 事件再换（`SessionManager::adopt`）。旧窗口收到 `moved` 时已写完之前的全部输出，这时用 `@xterm/addon-serialize` 序列化屏幕与回滚，经后端转交（`session-snapshot`）；目标窗口按原尺寸写入快照和在此期间缓存的输出（不丢不重；程序是按旧尺寸输出的），画完才适配窗格，并把新尺寸告诉会话一次；画完之前终端的尺寸变化不转给会话。每次移动由目标窗口取一个 id（`moveId`），随 `moved` 和快照往返，迟到的旧快照不会被当成这次的。addon 不保存的状态（SGR 鼠标编码、隐藏光标、光标形状、滚动区域）从 xterm.js 内部读出附在快照后（`lib/terminalModes.ts`）。会话在 `session_adopt` 返回时就归目标窗格（输入直达，关闭窗格会结束它），但画完快照前不能再移走。旧窗口还没确认的输出不再计入流控，旧窗口迟到的确认被忽略。没有会话的窗格直接带上快照，等待重连的立即重连；旧窗口里的这类窗格在移动期间不再连接（重试计时、网络恢复、回车），移动失败才恢复，以免两边各连一次。全部会话移走后旧窗口关掉这个标签。目标窗口接管失败（会话刚结束、ZMODEM 刚开始）时去掉这个窗格并告诉来源窗口（`pane-stayed`）；目标窗口在接管完之前关闭时，来源窗口从 `window-closed` 得知。没移走的窗格留在来源窗口，标签的其余部分照常移走。
- **不能移动的标签**：文件面板有传输、本地编辑或待回答的问题，ZMODEM 进行中，窗格正在打开会话，或会话还在移入（快照还没画完）。这些状态属于旧窗口的页面（进度 Channel、文件对话框），菜单项此时禁用；后端也拒绝 ZMODEM 中的会话（`session.busy`）。文件面板在新窗口里重新打开，从主目录开始。
- **拖出标签**（`tab_drag.rs`）：在标签栏里拖动照常排序；拖出窗口后松手，落在另一个窗口的标签栏上就并入那里的对应位置，落在其他地方（包括另一个窗口的终端区）就在光标处开新窗口（保持在屏幕的工作区内）；窗口唯一的标签拖到其他地方什么也不做；Esc 取消并恢复原来的顺序。仍用鼠标事件：WKWebView 在按住按键移出窗口后照样收到 `mousemove` / `mouseup`，松手没被页面收到时以 `buttons === 0` 兜底。拖动中页面一次一个请求地问后端会落在哪里：落点窗口由系统判断（macOS `windowNumberAtPoint`、Windows `WindowFromPoint`），被其他应用的窗口挡住的 ZShell 窗口不算；光标用后端读的屏幕坐标，不用网页的 `screenX`（多显示器、缩放不同时不可靠）：macOS 上统一换成点（tao 给的各个位置各按自己显示器的缩放换算），其他平台用物理像素（逻辑坐标在各显示器上含义不同），所以新窗口先隐藏着创建，定好位置再显示。每次拖拽有页面给的 id，拖拽结束后才返回的询问不再显示插入位置。各窗口报告自己标签栏的矩形；落点窗口收到 `tab-drag-over` 显示插入位置，并入时按松手的横坐标算出位置。
- **关闭与退出**：窗口的最后一个标签关闭或移走时，如果还有其他窗口，这个窗口随之关闭；只剩一个窗口时留下空窗口。关空窗口由后端判断（`window_close_empty`）：有待取的标签就不关，关了就不再接收标签（`window_send_tab` 报 `window.notFound`），前端正在取标签时也不去关。关掉最后一个窗口即退出。⌘Q 由有焦点的窗口处理：后端向每个窗口询问需要确认的标签数（`busy-query`），合计后确认一次再退出；超时未答的窗口（页面还在加载）按它拥有的会话数计，宁可多问。

### 状态栏

- **内容**：`StatusBar` 显示当前窗格的连接、上下行指示灯、终端类型、尺寸与光标，可在设置里关闭。
- **数据来源**：变化少的（终端类型、重连时间）在 tab store；变化频繁的（收发计数、光标）不进 store，状态栏直接订阅并按帧更新（`lib/traffic.ts`、`TerminalView`）。计数只算终端数据，不含 SFTP 与转发。
- **无障碍**：状态栏不是 live region（光标一动就会播报），各项的读屏名称是完整句子。

## 平台注意事项

- macOS 上 CJK 输入法要在真机上测。处理 Enter / Esc 前先用 `lib/platform.ts` 的 `isComposing` 判断是否在组字。
- macOS 的"按住按键显示重音字符"被关掉（与 Terminal.app 一致），长按会重复；用户可用 `defaults write` 恢复（`lib.rs`）。
- 中文 / emoji 宽度依赖 unicode11 插件。
- Windows 的 S 模式不允许启动命令行程序，这时隐藏本地终端的入口，其他功能不受影响。
- ConPTY 需要 Windows 10 1809 及以上。Windows PowerShell 5.1 调用的原生程序可能按 OEM 代码页输出导致中文乱码，暂不修改用户的 `[Console]::OutputEncoding`（已知限制）。
- ssh-agent：macOS 用 `SSH_AUTH_SOCK`；Windows 用 OpenSSH 命名管道或 Pageant。

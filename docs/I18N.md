# ZShell 国际化（i18n）

## 语言约定

- `docs/` 目录下的文档使用中文；除此之外的一切（代码、注释、README、CHANGELOG、提交信息）使用英语。
- 应用的源语言为英语；界面文案、终端提示、错误信息的其他语言由各自的语言包提供（`i18n.rs` 的 `SOURCES`）。
- 每种语言都是完整翻译：新增或修改英语文案时，在同一个提交里更新所有语言，测试会拦下缺失的 key。

## 文案来源与处理方式

| 来源 | 示例 | 处理 |
|---|---|---|
| 前端界面 | 按钮、对话框、提示、传输状态 | 前端 `i18next` 按 key 翻译 |
| 后端命令错误 | `Cannot list {path}`、`Session profile not found` | 后端消息目录按当前语言渲染，连同 `code` / `params` 返回 |
| 后端写入终端的提示 | 主机指纹确认、连接关闭、口令错误 | 后端消息目录按当前语言渲染 |
| macOS 菜单栏、Touch ID / Windows Hello 提示 | Edit、Copy、Hide ZShell | 后端消息目录 |
| 远端/系统产生的文本 | 服务器 banner、keyboard-interactive 问题、SFTP 状态、OS 错误、文件对话框 | 原样显示，不翻译（作为错误的技术细节附在译文之后） |

每条文案只在一处维护：界面文案在前端语言包，后端产生的文案在后端语言包。

## 目录与格式

- 前端：`src/locales/<lang>.json`；后端：`src-tauri/locales/<lang>.json`（编译期嵌入）。
- 两端都是嵌套 JSON，key 为点分路径（`sftp.uploadFiles`、`errors.transfer.readFailed`），占位符统一为 `{name}`。
- 前端复数用 i18next 的后缀约定（`transfer.progress_one` / `_other`，参数 `count`），按 `Intl.PluralRules` 选择。每种语言要有它的全部复数类别：中文、日语只有 `_other`，德语 `_one` / `_other`，法语 `_one` / `_many` / `_other`（缺一个类别时 i18next 会用英语的那一条）。英语有 `_zero` 的 key（数量为 0 时 i18next 优先用它，不论语言），其他语言也要有。
- 英语为源语言，也是缺失 key 时的兜底。

## 语言的选择

- `settings.json` 的 `language` 为 `"system"` 或一个语言代码；设置界面在「外观」一节，各语言用自己的名字（`Intl.DisplayNames`）。"恢复默认"不改语言。
- 后端决定语言（`i18n.rs`）：启动时读设置，`"system"` 时按系统的首选语言列表（`sys-locale`）找第一个有语言包的；保存设置时随之切换。中文按文字匹配：`zh-CN`、`zh-SG` → `zh-Hans`；`zh-TW`、`zh-HK`、`zh-MO` 是繁体，不回退到简体。由后端而不是页面决定：后端的文本（菜单栏、Touch ID / Windows Hello 的提示）在任何页面加载之前就要用对语言；WebView 的 `navigator.languages` 也不可靠（WKWebView 只报应用声明过的本地化，WebView2 报的是浏览器界面语言）。
- 前端启动时从 `locale_get` 取后端选好的语言再初始化 i18next；设置变化时（本窗口或其他窗口，经 `config-changed`）按同样规则切换，立即生效。已经写进终端的提示、已写入的日志保持原来的语言。
- 支持的语言只在后端的 `SOURCES` 里登记，经 `bindings.ts` 的 `LANGUAGES` 给前端；前端的 `resources` 必须与它一致（类型检查）。

## 前端

- `src/i18n/index.ts`：初始化 i18next（插值前后缀改为 `{` `}`，与后端一致）；切换语言时设置 `<html lang>`（断字、本地字形）、`data-cjk`（见下文字体）和快捷键里的键名。
- `src/i18n/i18next.d.ts`：以 `en.json` 为类型源，`t()` 的 key 写错会在 `tsc` 阶段报错。其他语言不进类型检查，由测试保证。
- `src/locales/locales.test.ts`：`en.json` 里没用到的 key 让测试失败。key 算作用到：源码（含 `bindings.ts`）里有它的字符串字面量（复数 key 看去掉 `_one` / `_other` 后缀的部分），或者有以它开头的动态 key（`` `proxy.kinds.${kind}` ``），且剩下的部分（`socks5`）作为字符串出现在源码里。同一文件还检查每种语言：key 与 `en.json` 一致（复数按该语言的类别）、没有空串、占位符与英语相同（复数形式可以省略 `{count}`）。
- 组件中用 `useTranslation()` 的 `t()`；写入 xterm 的提示同样走 `t()`。
- 日期与数字用 `Intl.DateTimeFormat` / `Intl.NumberFormat` 按当前语言格式化（`src/lib/format.ts`）。
- 后端错误用 `errorMessage()` 显示，逻辑判断用 `errorCode()`（例如传输取消判断 `transfer.cancelled`），不匹配文案内容。
- 快捷键的修饰键与命名键（`keys.*`）按语言显示：德语 `Strg` / `Umschalt`，法语 `Maj`；macOS 的符号不变。

## 后端

- `src-tauri/src/i18n.rs`：消息目录、语言协商、当前语言；`t!("key", name = value)` 宏取译文。
- `error::Error` 为 `{ code, params, detail }`：消息由 `errors.<code>` 渲染，底层原因（OS / 库 / 服务器文本）作为不翻译的 `detail` 追加；序列化给前端为 `{ code, params, message }`；前端的 `code` 类型是从 `errors.*` 生成的 `ErrorCode`（见 [ARCHITECTURE.md](ARCHITECTURE.md)「前后端类型」）。后端内部通过 anyhow 的 `.context(Error::new(..))` 附加，转换回 `Error` 时取最外层的 code。
- 单元测试 `catalog_covers_all_keys_in_sources` 扫描源码中的 `t!("…")` 与 `Error::new("…")`，确保英语语言包包含所有 key；`catalog_has_no_unused_keys` 要求英语语言包的每个 key 都在源码里以字符串字面量出现（错误码可以不带 `errors.` 前缀，因为有的 key 先选好再传给 `t!`）；`catalogs_are_complete` 要求其他语言的 key 与英语一致、没有空串、占位符相同。
- OpenSSH 风格、用户可能依赖其字面形式的提示保持英文，不进语言包：`user@host's password:`、`Enter passphrase for key '…':`、`Permission denied, please try again.`，以及 `(yes/no)` 的回答词。删除保险库时要输入的确认词 `DELETE` 同样各语言一致（`UnlockScreen.tsx`），不用切换输入法。主机密钥警告的 `@` 方框（`hostKey.*Banner`）在各语言里也保持英文原样，方框里的宽度按英语对齐。

## 平台

- macOS：`src-tauri/Info.plist` 的 `CFBundleLocalizations` 列出所有语言，否则系统认为应用只有英语。菜单栏的预置项（About、Hide、Copy……）由后端传入译文；AppKit 自己加的项（服务菜单的内容、"开始听写"、进入全屏）、文件对话框与 Touch ID 对话框的其余部分跟随系统语言。
- Touch ID 的理由（`appLock.reasonMacos`）由系统拼进它自己的句子："“ZShell”正在尝试{理由}。"，各语言的译文要接得上系统那句话（见下文风格）。
- Linux：polkit 策略文件（`linux/org.boyin.zshell.policy`）的 `description` / `message` 各语言一份 `xml:lang`（POSIX 名称，简体中文为 `zh_CN`）；polkit 按认证代理所在会话的语言选择，与 ZShell 的设置无关。
- 测试 `packages_declare_every_language` 检查上面两个文件列出了所有语言。

## 字体

- 界面字体栈：系统的拉丁字体在前（`-apple-system`、`Segoe UI`、`system-ui`），德语、法语、西里尔字母都由它们覆盖；CJK 回退字体 `--font-cjk` 在后——CJK 字体也带拉丁与西里尔字母，排在前面会用它们的字形。macOS 的 `-apple-system` 自带汉字，按 `<html lang>` 选字形；Windows 的 `system-ui` 是系统界面字体（日文 Windows 上是 Yu Gothic UI），会以日文字形画中文界面的汉字，所以 Windows 上 `--font-cjk` 排在 `Segoe UI`（没有汉字）之后、`system-ui` 之前。
- 汉字统一编码后，同一码位在中、日、韩字体里字形不同，所以 CJK 回退的顺序由 `<html data-cjk>` 决定：界面是 CJK 语言时就是它，否则取系统首选语言里的第一个 CJK 语言（后端 `Locales.cjk`），都没有则用简体中文。终端字体（`terminalSchemes.ts`）的 CJK 回退用同一个值。
- 设置里的「应用字体」（`appFont`）排在整个字体栈之前（`--app-font`），它缺少的字符仍按上面的顺序回退；页面无法解析的值被忽略，以免整个界面退回浏览器默认字体。
- 保加利亚语、塞尔维亚语等的本地字形由字体的 OpenType `locl` 特性按 `<html lang>` 启用，不需另设字体。

## 新增一种语言

1. 新建 `src/locales/<lang>.json` 和 `src-tauri/locales/<lang>.json`，按英语文件逐 key 完整翻译，遵循下文的风格与术语表（术语表加一列）。
2. 在 `src-tauri/src/i18n.rs` 的 `SOURCES`、`src/i18n/index.ts` 的 `resources` 中登记，运行 `UPDATE_BINDINGS=1 cargo test bindings`。
3. 在 `src-tauri/Info.plist` 与 polkit 策略文件里加上该语言。
4. 是 CJK 语言而 `Cjk` 没有它时，在 `i18n.rs`、`styles.css`、`terminalSchemes.ts` 加一组回退字体。
5. 端到端走一遍主要界面，检查布局与字形。

## 翻译风格

通用：

- 译文是给用户看的完整句子，按目标语言重新组织语序，不逐词对应；占位符可以移动位置，但不能增删。
- 菜单项与按钮打开对话框时带省略号 `…`，与英语一致；英语的 Title Case 不照搬，各语言按自己的大小写规则（德语名词大写，法语句首大写）。
- 引号：英语的 “…” 与 "…" 换成目标语言的引号。
- 文案里写到的按键（`Ctrl+C`、`Shift+Enter`）按目标语言键盘上的写法（德语 `Strg+C`、`Umschalt+Eingabe`，法语 `Maj+Entrée`）；macOS 专用的文案（Option 键）用 Apple 在该语言里的叫法。
- 平台的名称用该平台官方的译名（下表），协议名与配置关键字不译。
- 与 OpenSSH 相同的终端提示（主机密钥确认等）参照 OpenSSH 的行文，但 OpenSSH 本身没有翻译，以清楚为先。

简体中文：

- 用"你"，或省略人称；不用"您"。
- 中文与英文、数字之间加空格（`SSH 会话`、`3 个文件`），与全角标点之间不加。
- 全角标点；引号用 “”；英语的冒号列表（`Sends to: {names}`）用全角冒号。
- Touch ID 理由接在"“ZShell”正在尝试"之后：`显示你的会话`。

日语：

- 句子用です・ます体；按钮、菜单、标签用名词或动词词干（「保存」「接続」），不用です・ます。
- 全角括号与标点；引号用「」；与英文、数字之间不加空格。
- 外来语长音按 Microsoft / Apple 的写法（「フォルダー」「サーバー」「ユーザー」）。
- Touch ID 理由接在"“ZShell”が…しようとしています"之中：`セッションを表示`。

德语：

- 用 "Sie"；按钮与菜单用不定式（`Datei hochladen`），提示与说明用完整句子。
- 引号用 „…“；复合词按德语规则连写或加连字符（`SSH-Sitzung`、`Port-Weiterleitung` 除外见术语表）。
- 说明与提示等段落里的长词由 `hyphens: auto` 断开（标签与按钮只在词间换行），不为布局缩写单词。
- Touch ID 理由接在"„ZShell“ versucht, …"之后：`Ihre Sitzungen anzuzeigen`。

法语：

- 用 "vous"；按钮与菜单用不定式（`Téléverser des fichiers`）。
- `:` `;` `?` `!` 与 `»` 之前、`«` 之后用不换行空格（`:` 前用 U+00A0，`;` `?` `!` 前用 U+202F）。
- 引号用 « … »。
- Touch ID 理由接在"« ZShell » tente de …"之后：`afficher vos sessions`。

## 开发约束

- 新文案一律加入语言包，不在组件或后端代码里写死用户可见的文本；同一个提交里补齐所有语言。
- 用完整句子加参数，不拼接句子片段（便于不同语序的语言翻译）。
- 不根据文案内容做逻辑判断，用错误码或状态。
- 界面布局不假设文案长度（德语通常比英语长三成）；大小写等样式用 CSS（`text-transform`）实现。
